# CloudBridge Deep Security Audit (`f97ff8e3`) & Weaker-Agent Remediation Prompt Pack

## 1. Executive Summary & Baseline Reconciliation

This report presents the results of a **deep security audit (`profile: "deep"`)** of `thies2005/cloudbridge` (`de.schuelken.cloudbridge`, version `2.5.39` / `versionCode 84`, commit `f97ff8e3c84fa3f58657a660afaf603c7c5eb6d1`) and provides a **deterministic, zero-ambiguity prompt pack** engineered specifically for weaker/smaller AI coding agents to implement all fixes safely.

## 2. Architecture & Trust Boundaries

CloudBridge consists of two Gradle modules (`:app` and `:safdav`) and a native Go cross-compilation task (`:rclone:buildRclone`) that builds `librclone.so` from `rclone` commit `b6c5bf4ba499ff2dd617bdabdfba13e033c5d999`. Across the application, six primary trust boundaries govern security:
1. **Exported `VirtualContentProvider` (`android.permission.MANAGE_DOCUMENTS`)**: Exposes cloud remotes to Android's Storage Access Framework (`DocumentProvider`). While `MANAGE_DOCUMENTS` restricts initial picker selection to the system UI, once a user grants a third-party app access to a single folder via `ACTION_OPEN_DOCUMENT_TREE`, Android delegates all descendant path authorization for that caller to `VirtualContentProvider.isChildDocument(parentDocumentId, documentId)`.
2. **Localhost Daemons (`SafDAVServer`, `RcloneRcd`, `StreamingService`)**: Android grants `android.permission.INTERNET` to almost every app on the device. Any TCP port bound to `127.0.0.1` (`SafDAVServer` on `:21453`, `RcloneRcd`, or `StreamingService` on `:8080`) is reachable by every local app on the phone and must enforce cryptographic authentication or a high-entropy capability URL.
3. **Exported `MainActivity` & `SharingActivity` Intent Surface**: Both activities are exported in `AndroidManifest.xml`. Any app on the device can send explicit `Intent`s with custom actions (`MAIN_ACTIVITY_START_IMPORT`, `MAIN_ACTIVITY_START_EXPORT`, `MAIN_ACTIVITY_START_REAUTH`) or crafted `content://` / `file://` URIs.
4. **`FileProvider` (`de.schuelken.cloudbridge.fileprovider`)**: Bridges internal cache directories (`getCacheDir()/preview`, `getCacheDir()/share_staging`, `getCacheDir()/report`) to external viewer apps via temporary `FLAG_GRANT_READ_URI_PERMISSION` grants.
5. **`Rclone` CLI Process Execution Boundary**: `Rclone.java` constructs command arrays passed to `Runtime.getRuntime().exec(command, env)`. User- or backup-controlled remote names, file paths, and passwords must be separated from rclone flags via `"--"`.
6. **Config & Backup Import Boundary (`rclone.conf`, `export.json` inside `.zip`)**: Imported configuration archives populate `rclone.conf`, the SQLite `Task`/`Trigger` tables (`Importer.java`), and `SharedPreferences` (`SharedPreferencesBackup.java`).

## 1. [HIGH] `download-and-open-fileprovider-root-crash-and-cache-lifecycle` — DownloadAndOpen Crashes on Every File Preview Due to Missing FileProvider Root in file_provider_paths.xml and Uncleaned Internal Cache

- **Verdict**: `confirmed` | **Severity**: `HIGH` (Likelihood: `high`, Impact: `high`) | **Confidence**: `high`
- **Trace Locations**: `app/src/main/java/ca/pkay/rcloneexplorer/Fragments/FileExplorerFragment.java:1853`, `app/src/main/res/xml/file_provider_paths.xml:3`, `app/src/main/java/ca/pkay/rcloneexplorer/Fragments/FileExplorerFragment.java:1908`

### Description & Root Cause
FileExplorerFragment.DownloadAndOpen saves previewed files to new File(context.getCacheDir(), 'preview'), but app/src/main/res/xml/file_provider_paths.xml only configures external-cache-path '/' and cache-path 'report/'. Calling FileProvider.getUriForFile on any file in getCacheDir()/preview throws IllegalArgumentException. Additionally, MainActivity.onDestroy only cleans getExternalCacheDir(), leaving decrypted preview and share_staging files in getCacheDir() indefinitely.

- **Root Cause**: Prior remediation TASK-W2-04 moved DownloadAndOpen staging to context.getCacheDir()/preview without adding &lt;cache-path name=&quot;preview&quot; path=&quot;preview/&quot;/&gt; to file_provider_paths.xml or updating MainActivity.onDestroy cache cleanup.
- **Intended Behavior**: file_provider_paths.xml must declare &lt;cache-path name=&quot;preview&quot; path=&quot;preview/&quot;/&gt; (and remove the broad external-cache-path '/'), and MainActivity.onDestroy must purge getCacheDir()/preview and getCacheDir()/share_staging.

### Source-to-Sink Trace
- **`ENTRYPOINT`** (`app/src/main/java/ca/pkay/rcloneexplorer/Fragments/FileExplorerFragment.java:1853`, `FileExplorerFragment.DownloadAndOpen.doInBackground`): Downloads the selected cloud file into new File(context.getCacheDir(), "preview").
- **`PROPAGATION`** (`app/src/main/res/xml/file_provider_paths.xml:3`, `paths`): Defines only &lt;external-cache-path name=&quot;cache&quot; path=&quot;/&quot;/&gt; and &lt;cache-path name=&quot;internal-cache&quot; path=&quot;report/&quot; /&gt;, omitting cache-path "preview/".
- **`SINK`** (`app/src/main/java/ca/pkay/rcloneexplorer/Fragments/FileExplorerFragment.java:1908`, `FileExplorerFragment.DownloadAndOpen.onPostExecute`): Calls FileProvider.getUriForFile(context, BuildConfig.APPLICATION_ID + ".fileprovider", new File(fileLocation)), throwing IllegalArgumentException.

### Code Evidence
- `app/src/main/res/xml/file_provider_paths.xml:4` — Only internal cache subdirectory 'report/' is registered for FileProvider.
- `app/src/main/java/ca/pkay/rcloneexplorer/Activities/MainActivity.java:369` — onDestroy deletes files only in getExternalCacheDir(), leaving internal getCacheDir()/preview and share_staging files on disk.

### Exploitation & Verification
- **Attacker Perspective**: Any user opening a cloud file triggers an unhandled IllegalArgumentException in DownloadAndOpen.onPostExecute, while the downloaded plaintext file remains uncleaned in /data/data/de.schuelken.cloudbridge/cache/preview/.
- **Observed Result**: FileProvider.getUriForFile throws IllegalArgumentException: Failed to find configured root that contains /data/data/de.schuelken.cloudbridge/cache/preview/..., and downloaded files persist in internal cache after app exit.
- **Payloads / Reproduction Inputs**:
  - `/data/data/de.schuelken.cloudbridge/cache/preview/document.pdf`

### Impact & Likelihood
- **Impact (`high`)**: Completely breaks file open/preview functionality with an uncaught crash while leaving decrypted cloud files uncleaned in internal cache.
- **Likelihood (`high`)**: Triggers deterministically on 100% of file preview/open actions.

### Remediation Strategy
Update app/src/main/res/xml/file_provider_paths.xml to add &lt;cache-path name=&quot;preview&quot; path=&quot;preview/&quot; /&gt; and scope external-cache-path to a dedicated subdirectory, and update MainActivity.onDestroy to clean internal preview and share_staging directories.

## 2. [HIGH] `main-activity-exported-custom-actions-and-external-config-import` — Exported MainActivity Accepts Unprotected Custom Intent Actions for Config Import/Export and Crashes on Null MIME Type

- **Verdict**: `confirmed` | **Severity**: `HIGH` (Likelihood: `medium`, Impact: `high`) | **Confidence**: `high`
- **Trace Locations**: `app/src/main/java/ca/pkay/rcloneexplorer/Activities/MainActivity.java:198`, `app/src/main/java/ca/pkay/rcloneexplorer/Activities/MainActivity.java:235`, `app/src/main/java/ca/pkay/rcloneexplorer/Activities/MainActivity.java:749`

### Description & Root Cause
MainActivity is exported (android:exported="true") and unconditionally dispatches custom actions (MAIN_ACTIVITY_START_IMPORT, MAIN_ACTIVITY_START_EXPORT, MAIN_ACTIVITY_START_REAUTH, MAIN_ACTIVITY_START_LOG) in onCreate and onNewIntent. Any third-party app can launch MainActivity into the config import/export or re-auth flows, and if searchExternalConfig() finds a planted rclone.conf in shared external storage, CopyConfigFile.doInBackground crashes with a NullPointerException because ContentResolver.getType(fileUri) returns null.

- **Root Cause**: MainActivity.handleIntentAction does not restrict internal actions to same-UID callers, searchExternalConfig reads world/media-accessible external storage, and CopyConfigFile calls mime.equals("application/zip") without a null check.
- **Intended Behavior**: MainActivity should ignore internal custom actions from external UIDs (or only accept ACTION_MAIN), remove automatic external storage config discovery, and use "application/zip".equals(mime) in CopyConfigFile.

### Source-to-Sink Trace
- **`ENTRYPOINT`** (`app/src/main/java/ca/pkay/rcloneexplorer/Activities/MainActivity.java:198`, `MainActivity.onCreate / onNewIntent`): Receives an external Intent and passes it to handleIntentAction(intent).
- **`PROPAGATION`** (`app/src/main/java/ca/pkay/rcloneexplorer/Activities/MainActivity.java:235`, `MainActivity.handleIntentAction`): Invokes startConfigImportFlow(), startConfigExportFlow(), or handleReauthIntent(intent) without checking the sender.
- **`SINK`** (`app/src/main/java/ca/pkay/rcloneexplorer/Activities/MainActivity.java:749`, `MainActivity.CopyConfigFile.doInBackground`): Calls mime.equals("application/zip") where resolver.getType(uris[0]) is null for file:// URIs returned by searchExternalConfig().

### Code Evidence
- `app/src/main/AndroidManifest.xml:47` — MainActivity is declared with android:exported="true".
- `app/src/main/java/ca/pkay/rcloneexplorer/Rclone.java:1627` — searchExternalConfig() scans getExternalFilesDirs(null) for rclone.conf and returns a file:// Uri.

### Exploitation & Verification
- **Attacker Perspective**: A local app sends an explicit Intent to de.schuelken.cloudbridge/.Activities.MainActivity with action MAIN_ACTIVITY_START_EXPORT or MAIN_ACTIVITY_START_IMPORT.
- **Observed Result**: External apps can force CloudBridge into config import/export or Internxt re-authentication dialogs, and importing a file:// URI crashes with NullPointerException.
- **Payloads / Reproduction Inputs**:
  - `Intent("MAIN_ACTIVITY_START_IMPORT").setClassName("de.schuelken.cloudbridge", "ca.pkay.rcloneexplorer.Activities.MainActivity")`

### Impact & Likelihood
- **Impact (`high`)**: Enables UI spoofing/phishing of config import/export and 2FA re-auth flows, and crashes config import on file:// URIs.
- **Likelihood (`medium`)**: Trivially invokable by any local app via startActivity().

### Remediation Strategy
Require an internal boolean token or direct fragment/activity callback instead of unverified external Intent actions in MainActivity, remove external storage auto-discovery in startConfigImportFlow, and replace mime.equals("application/zip") with "application/zip".equals(mime).

## 3. [HIGH] `safdav-provider-paths-permission-prefix-and-move-destination-bypass` — SafDAVServer and ProviderPaths Substring Permission Match and Unvalidated Destination Header Enable SAF Scope Escape

- **Verdict**: `confirmed` | **Severity**: `HIGH` (Likelihood: `medium`, Impact: `high`) | **Confidence**: `high`
- **Trace Locations**: `safdav/src/main/java/io/github/x0b/safdav/SafDAVServer.java:394`, `safdav/src/main/java/io/github/x0b/safdav/SafDAVServer.java:401`, `safdav/src/main/java/io/github/x0b/safdav/saf/ProviderPaths.java:143`

### Description & Root Cause
ProviderPaths.getUriByMappedPath validates persisted UriPermissions using pathPrefix.contains(permissionPath) without enforcing a path-segment boundary or rejecting '..' traversal segments, and appends raw pathExtra directly to storedUri.getPath(). Furthermore, SafDAVServer.onMove slices the HTTP Destination header by SafConstants.SAF_REMOTE_URL.length() - 1 without verifying that the header starts with SAF_REMOTE_URL or checking length bounds.

- **Root Cause**: ProviderPaths.getUriByMappedPath uses substring containment (.contains) instead of canonical segment-boundary prefix checking and does not reject '..' segments; SafDAVServer.onMove performs unchecked substring slicing on the Destination header.
- **Intended Behavior**: ProviderPaths.getUriByMappedPath must reject '..' and '.' path segments and require permissionPath to match at a '/' or ':' boundary, and SafDAVServer.onMove must validate that Destination starts with SafConstants.SAF_REMOTE_URL before slicing.

### Source-to-Sink Trace
- **`ENTRYPOINT`** (`safdav/src/main/java/io/github/x0b/safdav/SafDAVServer.java:394`, `SafDAVServer.onMove / onGet / onPut / onDelete`): Receives HTTP WebDAV request URI and Destination header and passes them to paths.getUriByMappedPath().
- **`PROPAGATION`** (`safdav/src/main/java/io/github/x0b/safdav/SafDAVServer.java:401`, `SafDAVServer.onMove`): Calls destination.substring(SafConstants.SAF_REMOTE_URL.length() - 1) without checking length or prefix.
- **`SINK`** (`safdav/src/main/java/io/github/x0b/safdav/saf/ProviderPaths.java:143`, `ProviderPaths.getUriByMappedPath`): Checks if (pathPrefix.contains(permissionPath)) and constructs a content://com.android.externalstorage.documents/tree/ URI without rejecting '..' traversal.

### Code Evidence
- `safdav/src/main/java/io/github/x0b/safdav/saf/ProviderPaths.java:119` — Appends unvalidated pathExtra directly to storedUri.getPath().
- `safdav/src/main/java/io/github/x0b/safdav/saf/ProviderPaths.java:143` — Uses pathPrefix.contains(permissionPath) instead of startsWith with a segment boundary.

### Exploitation & Verification
- **Attacker Perspective**: A caller to SafDAVServer or SafDirectServer supplies a path containing '/../' or a sibling folder prefix (e.g., /primary/WorkSecret when only /primary/Work is permitted) or a short Destination header on MOVE.
- **Observed Result**: ProviderPaths maps paths outside the intended SAF tree scope, and SafDAVServer.onMove throws an uncaught StringIndexOutOfBoundsException on short Destination headers.
- **Payloads / Reproduction Inputs**:
  - `MOVE /Internal%20Storage/test.txt HTTP/1.1\r\nDestination: /short`

### Impact & Likelihood
- **Impact (`high`)**: Bypasses SAF folder-level permission boundaries and allows out-of-tree file access or server crash.
- **Likelihood (`medium`)**: Reachable through SAF path mapping and WebDAV MOVE/GET/PUT requests.

### Remediation Strategy
Reject any requestUri containing '..' segments or backslashes in ProviderPaths.getUriByMappedPath, enforce exact prefix boundary matching on permissionPath, and validate destination.startsWith(SafConstants.SAF_REMOTE_URL) in SafDAVServer.onMove.

## 4. [HIGH] `vcp-is-child-document-traversal-and-prefix-bypass` — VirtualContentProvider.isChildDocument Path Traversal and Sibling-Prefix Confusion Enable Scoped Directory Grant Escape

- **Verdict**: `confirmed` | **Severity**: `HIGH` (Likelihood: `medium`, Impact: `high`) | **Confidence**: `high`
- **Trace Locations**: `app/src/main/java/ca/pkay/rcloneexplorer/VirtualContentProvider.java:226`, `app/src/main/java/ca/pkay/rcloneexplorer/VirtualContentProvider.java:1201`, `app/src/main/java/ca/pkay/rcloneexplorer/VirtualContentProvider.java:1324`

### Description & Root Cause
VirtualContentProvider.isChildDocument(String parentDocumentId, String documentId) is the Android DocumentsProvider access-control callback enforced by DocumentsProvider.enforceTree(Uri) for scoped directory grants (ACTION_OPEN_DOCUMENT_TREE). Line 227 implements it as 'return documentId.startsWith(parentDocumentId);' without checking for a '/' path-segment boundary or rejecting '..' parent-directory traversal segments. Any third-party app granted access to a single subfolder on a remote can access sibling folders or traverse via '..' to read, write, or delete arbitrary files across the entire cloud remote.

- **Root Cause**: VirtualContentProvider.isChildDocument performs a raw string prefix check (startsWith) without path-segment boundary enforcement or '..' traversal rejection, and getFileItem/openDocument pass the unnormalized path to rclone.
- **Intended Behavior**: VirtualContentProvider.isChildDocument (and getNoRootId/getFileItem) must reject any documentId containing '..' or '.' path segments, verify both IDs belong to the same remote, and require a '/' separator boundary after parentDocumentId.

### Source-to-Sink Trace
- **`ENTRYPOINT`** (`app/src/main/java/ca/pkay/rcloneexplorer/VirtualContentProvider.java:226`, `VirtualContentProvider.isChildDocument`): Called by Android DocumentsProvider.enforceTree(Uri) to verify whether a requested documentId falls within a caller's granted tree URI.
- **`PROPAGATION`** (`app/src/main/java/ca/pkay/rcloneexplorer/VirtualContentProvider.java:1201`, `VirtualContentProvider.getFileItem`): Splits documentId and queries rcd.list(remote[0], dirPath) without rejecting '..' segments.
- **`SINK`** (`app/src/main/java/ca/pkay/rcloneexplorer/VirtualContentProvider.java:1324`, `VirtualContentProvider.openDocument`): Streams file contents via rclone.downloadToPipe(documentId) or overwrites via rclone.uploadFromPipe(documentId).

### Code Evidence
- `app/src/main/java/ca/pkay/rcloneexplorer/VirtualContentProvider.java:227` — Returns documentId.startsWith(parentDocumentId) with no '/' boundary check or '..' normalization.
- `app/src/main/java/ca/pkay/rcloneexplorer/VirtualContentProvider.java:793` — deleteDocument, renameDocument, copyDocument, and moveDocument also rely on enforceTree -> isChildDocument for tree URI authorization.

### Exploitation & Verification
- **Attacker Perspective**: An external app holding a tree grant to 'rclone/remotes/gdrive:/shared' requests 'rclone/remotes/gdrive:/shared_private/secret.txt' or 'rclone/remotes/gdrive:/shared/../../vault/passwords.kdbx' via ContentResolver.openInputStream or DocumentsContract.deleteDocument.
- **Observed Result**: isChildDocument returns true for sibling prefixes and '..' traversal paths, allowing unauthorized read, write, and delete operations outside the granted tree.
- **Payloads / Reproduction Inputs**:
  - `content://de.schuelken.cloudbridge.vcp/tree/rclone%2Fremotes%2Fgdrive%3A%2Fshared/document/rclone%2Fremotes%2Fgdrive%3A%2Fshared%2F..%2F..%2Fvault%2Fpasswords.kdbx`

### Impact & Likelihood
- **Impact (`high`)**: Completely defeats Android SAF directory scoping, allowing full read/write/delete access to the entire cloud remote.
- **Likelihood (`medium`)**: Exploitable by any local app that has been granted a scoped SAF folder permission via VirtualContentProvider.

### Remediation Strategy
